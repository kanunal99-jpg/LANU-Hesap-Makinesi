# Incoming call sound and visible actions

Reported: notification arrives but no ringtone or actionable incoming call screen, both locked/unlocked and foreground/background. Baseline release 1339, main 5df9229.

Root causes in code: PRIVATE notification supplied a title-only publicVersion, removing lock-screen actions when sensitive content is hidden; UI lifecycle ownership cancelled OS alerts before local ringtone readiness and did not restore after last host stopped; public Activity relied on a separate Compose Dialog; Android 35+ PendingIntent creator BAL opt-in was absent. Historical channel migration could inherit application-created null sound.

Changes: generic PUBLIC call notification/modern CallStyle or two-action fallback, immutable explicit call-only BAL opt-in, controls embedded in the secure show-when-locked Activity, resumed-host ownership and verified-only notification rearm on background transition. Notification fallback remains until the visible ringtone starts. New v5 channel preserves LOW/NONE, user-selected silence/custom sound and v4 vibration-off; API30+ repairs only app-created null sound with no historical user mute. Startup sanitizer renames without resetting channel properties. Settings refresh local notification/channel/ringer/DND/full-screen readiness on resume with existing direct OS-settings links.

No direct background Activity launch, no silent opt-in, no volume/DND override, no private navigation/PIN bypass, no media until verified INVITE plus explicit answer and runtime permission. Force-stop by Android settings prevents FCM until user reopens app. When unlocked Android may use persistent heads-up actions instead of covering another app; full-screen special access and OS/channel permissions remain necessary.

Tests cover public answer/decline PendingIntents, duplicate raw wake vs verified handoff, stale/revoked/visible suppression, channel migration silence and vibration preservation, API35/36 immutable explicit PendingIntents, sanitizer property preservation and real decrypted INVITE host/background/reject ownership without media creation. Existing authentication, anti-replay, answer permissions, two-way media and message regressions remain required. CI and physical acceptance are separate; physical Samsung A55 plus second phone must verify audible ringing and locked/unlocked actions. No field success is claimed from unit/emulator tests.
